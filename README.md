# demo1 英语默写批改

## 服务器部署候选版本（DEPLOY-IMPLEMENT-01）

新增 Docker Compose、Caddy、Gunicorn 单进程、独立数据目录与密钥文件配置。服务器版保留云端 Paddle OCR、多教师隔离和教师核对，不在镜像安装本地 Paddle 模型。默认仅绑定服务器回环地址，注册默认关闭；本轮未部署阿里云，也未开放公网。正式发布状态见 [改造与验收报告](docs/DEPLOY/DEPLOY-IMPLEMENT-01-REPORT.md)，不能以容器启动代替权限和恢复验收。

- [服务器实际操作手册](docs/DEPLOY/SERVER-OPERATIONS.md)
- [生产配置说明](docs/DEPLOY/PRODUCTION-CONFIG.md)
- Compose：`docker-compose.yml`；生产入口：`wsgi.py`；依赖：`requirements-server.txt`。下文本机启动方式不用于生产。

本版本供一位教师在本机使用，流程是：建立班级与名册 → 从 Excel 或 Word 建立任务并按班布置 → 上传照片 → 自动匹配学生 → 识别并自动计分 → 显示最终成绩 → 教师按需改判和导出。支持本机 PaddleOCR、PaddleOCR-VL 云端及 OpenAI 兼容图片接口。

## 启动

在 PowerShell 中进入项目目录，首次安装依赖：

```powershell
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

首次使用教师登录时，等后台批改完成后关闭本地网站，再在项目目录运行下面的命令。按提示设置账号和至少 8 个字符的密码，输入密码时终端不会显示内容。

```powershell
.venv\Scripts\python.exe -m flask --app app teacher-account
```

需要更换账号或重置密码时，先关闭网站并在同一条命令末尾加上 `--reset`。重置后旧登录会话失效。当前仅支持一位老师使用。

设置好账号后运行：

```powershell
.\start.ps1
```

也可以双击 `start.bat` 启动；启动窗口需要保持打开。

浏览器打开 <http://127.0.0.1:5000>。PaddleOCR 第一次识别会下载模型；照片和数据库保存在 `data/`，只监听本机地址。

## 班级与学生

### 日常工作入口（导航重构后）

首页按一次班级作业展示，默认20条，搜索及筛选作用于全部作业。点击作业名称固定进入成绩；“上传照片、成绩、待核对、讲评”可随时切换。姓名打开本次答卷，未交学生进入上传，不会建立空答卷。跨作业历史在“班级与学生”，标准答案和临时答卷在首页辅助入口“标准答案与布置”。

上传先选择、检查和移除文件，再提交。指定学生仍须教师对照原图明确确认。后台受理后可以离开，结束后提示查看成绩；不自动切页。仅重试明确失败的照片，响应不明先核对照片档案，不要整批重传。

待核对入口用“项”计数，归属按照片、不确定按题目、失败及待批改按答卷；普通错题不混入。异常队列判定后进入下一项，成绩或讲评中的修改保留当前题目。返回恢复筛选与位置；有草稿时可保存本答卷全部修改、放弃修改或继续编辑，部分失败时保留剩余草稿。

归档班级仅可查看历史成绩与讲评；恢复后才可上传或改判。正在批改时需等待结束再归档。在线讲评与工作区共用导航，下载仍生成可离线打开的HTML，打印与下载分开。服务器发布前请查阅 [部署准备审计](docs/DEPLOY/DEPLOYMENT-AUDIT.md)。

1. 打开“班级与学生”，建立班级，填写学年 / 学期。
2. 直接上传 Excel（`.xlsx`）或 CSV，也可复制“编号、姓名”两列粘贴。先预览，再确认导入；Excel 默认首个可见工作表，预览后可切换工作表并重新预览。有明确“编号 / 学号、姓名”表头时自动匹配，多余的班级等列不导入；例如“班级、姓名、学号”会取第 3 列作为班内编号、第 2 列作为姓名，预览显示匹配依据。若存在多个候选列或表头不明确，可展开“列顺序 / 多列名单设置”手动指定。旧版 `.xls` 请在 Excel 中另存为 `.xlsx`。
3. 打开默写任务，在“按班级收作业”中选择班级，保存本次应交名单。
4. 从班级任务名单选择学生，核对姓名和编号后上传。重复进入会打开同一答卷，可以补充多张照片。
5. 自动完成批改后，返回班级任务导出 Excel 或 CSV；点击题目可对照原图改判，无须逐题确认才能出成绩。

### 全班照片批量批改

打开班级任务页的“全班照片批量上传”，一次选择最多 100 张 JPG/PNG，点击“上传并自动批改”。系统先完成全部照片的文字识别，再统一执行两轮匹配，最后逐答卷自动计分。默认每人一张照片；多页作业请从学生答卷明确追加，或核对待处理照片后手动选择学生。

先用本次固定应交名单（排除免交）精确匹配学号或姓名，再用教师纠错记忆和相近姓名规则。多张照片指向同一学生会标记“疑似重复”，不会任取一张或转配别人。姓名末尾半角/全角数字仅在比较时忽略，整理后全名单重名仍须核对；原始名单名称保留。相近比较允许替换、增加或删除一个字，包括姓氏；两侧均为三至五个中文字、至少一侧为三至四字，且照片只有唯一姓名证据、剩余名单候选唯一、没有照片竞争或身份冲突时，才自动关联。例如“杜青禾 → 顾青禾”“欧阳月 → 欧阳明月”。二字姓名差异、两处差异、去数字后仍有错字只推荐人工候选；无姓名证据不强配，即使只剩一人也不例外。只有空答卷、尚无照片的学生仍可匹配。

页面显示已匹配人数、剩余学生和待处理照片；“重新匹配已有文字”不重复调用 OCR。待处理照片提供候选姓名、逐字差异和完整名单。单图入口复用相同规则；已有人工归属不会重新分配。

“更正推断归属”可将机器推断照片移给另一名本次应交学生并重新批改，保留审计记录，原学生恢复待交。仅允许原答卷为单页、全为机器处理，且目标没有照片或人工记录；有教师修改、人工核对、多页或正在批改时阻止覆盖。网络失败后可从已保存照片继续处理。

姓名推断是本机文字规则，不是模型置信度。独立中文行也作为姓名线索，因此与学生姓名相似的标题可能被误判；请优先在照片写明“姓名：”和学号，并核对推断标记。识别准确率与规则效果仍需真实样本验证，不使用名单辅助云端猜名。

“导出 Excel”与 CSV 使用同一份班级成绩数据：学号按文本写入，`001` 保持为 `001`；未交和免交的得分留空，暂定成绩与最终成绩分开显示。导出前未确认归属的照片不会进入成绩表。

### 教师姓名纠错记忆

核对照片并选择学生时，默认勾选“记住此姓名纠错，下次同班自动匹配”。请检查显示的“识别姓名 → 实际学生”；识别不到唯一姓名时，填写要记住的错名，或取消勾选。系统只记住老师明确确认的对应，机器匹配不会自行积累学习记录。旧版接口未传 `remember_identity` 时不自动保存记忆。

打开班级页右上角“姓名纠错记忆”，可查看来源照片、停用或启用对应关系。“历史纠错预览”默认不勾选，选择核对后才启用；缺少明确姓名证据的旧照片不自动导入。来源按学生档案保存，可在同班不同任务中使用，不影响其他班级。

匹配顺序为精确学号 / 姓名 → 教师纠错记忆 → 忽略姓名末尾数字后完全匹配 → 剩余名单一处编辑差异推断。记忆按错名完全匹配；冲突学号、精确姓名冲突、重复照片、多个姓名及本次免交不会被记忆绕过。同一错名启用多个学生对应时暂停匹配，可在管理页“仅保留此对应”。停用记忆不会改动已经保存的归属和成绩。

“教师纠错记忆”关联提供来源和安全更正入口。更正后停用触发错误的记忆，勾选记住时保存新的教师对应；有人工修改、多页或目标已上传时继续阻止覆盖。这里只改善姓名匹配，不训练 OCR；新的不同错名仍可能需要人工选择。各次匹配方式、人工选择与更正保存在照片记录、记忆来源和操作历史中，可用后续真实作业核对使用数量及误匹配次数。

后端回归在原命令末尾追加 `test_name_memory`。运行 5029 隔离测试服务器后，执行 `node scripts/check_name_memory_flow.cjs` 验证历史预览、显式启用、跨作业自动匹配和计分、安全更正、停启及手机布局；不调用真实云端。

### 识别接口配置

本机多教师模式仍可在“更多 → 识别设置”填写自己的接口；配置按当前教师隔离保存，其他账号不能查看或覆盖。旧版全局设置不会自动分配给新账号，需要在本人设置页重新填写。密钥不会在页面回显；只有点击“保存并测试图片连接”才会发起样例测试请求，可能计费。Staging/Production 仍使用平台部署配置，不向普通教师开放平台凭据编辑。

在侧栏打开“识别设置”。本机 PaddleOCR 不上传照片，但首次加载中文身份模型和 CPU 识别会较慢；OpenAI 兼容图片接口通常更快，需要填写 `https://.../v1` 地址、支持图片的模型和 API Key。系统实际请求 `POST /chat/completions`，图片以 base64 data URL 发送，API Key 不在页面回显，也不写入识别日志。云端识别返回的文字框只是参考，必须对照原图确认；接口测试可能产生服务商费用。

名单编号按文本保存，`001` 不会变成 `1`；Excel 数值 `1` 配合单元格格式 `000` 也会读为 `001`。长编号应在 Excel 中使用文本，已丢失的前导零或数值精度无法恢复。公式与错误单元格须先粘贴为值，不运行 Excel 公式。CSV 支持 UTF-8（含 BOM）与 GB18030，每次不超过 2 MB / 1000 人；Excel 最多 50 列，解压后内容不超过 20 MB。同编号同姓名重复跳过，同编号不同姓名阻止整批导入。同名或同编号不会跨班自动合并，请通过“添加已有学生”或“转班”明确关联档案。

布置时固定应交名单和当时的姓名 / 编号 / 班级。转班或改名保留旧作业显示，转入新生需在旧任务中手动补充；免交必须填写原因。学生档案可停用，班级可归档，历史不会删除。学生档案可查看历次成绩与未交记录。

未上传照片的空答卷仍算未交，CSV 分数留空；班级均分只计最终成绩。新传照片后自动重新批改；接口失败时显示失败并保留重试。机器批改和教师复核分别计数，教师修改保存即更新最终成绩。旧未归属答卷可在任务页展开“关联已有未归属答卷”，核对目标身份后手动关联；已有答卷不会被覆盖。

## 从 Word 建立语法填空任务

在“新建默写任务”中选择可编辑的 `.docx` 文件，点击“解析 Word 并预览题目”。首版识别 `(题号) ______` 形式的空格，并读取文末独立“答案 / 参考答案”区；例如题目中的 `(favor)` 会作为提示词，答案区的 `is favored` 作为标准答案。系统会保留题目上下文、提示词、原文和试题说明，预览阶段不会写入任务。

预览后逐题核对题号、上下文、提示词、答案和分值，勾选确认才会创建任务。语法填空默认每题 1 分；评分仍严格区分大小写、标点和词形。Word 中有多个答案候选、缺答案、公式、扫描图片或复杂版式时会提示人工处理，不使用模型猜答案。支持 `.docx`，不支持旧版 `.doc`；单文件不超过 5 MB，解压内容不超过 20 MB，最多 200 道题。

创建后，点击题目可查看“题目上下文、提示词、标准答案、学生作答”，打印答题纸不显示答案。原文空格作答按明确题号和题干后文自动定位；不能可靠定位的题目补识别后仍无结果时自动零分并标记不确定，教师可对照原图改判。也可以打印系统按题号生成的答题纸。

## 独立答题卡

在任务页或班级任务页点击“打印独立答题卡”，可直接打印或保存 A4 PDF；每页重复班级、学号、姓名和页码，不包含文章、提示词或标准答案。普通题每页最多十题，句子题预留三行。

上传时将“照片作答形式”选为“独立答题卡（按题号作答）”，再上传。单图、全班批量及答卷追加照片均支持；同一任务可混用两种纸张。独立答题卡按 `1. answer`、`2、 answer` 或 `(3) answer` 及后续行读取；普通空白纸也应写明题号、学号和姓名，并选择此模式。原文作答保持原有上下文分题方式。重复题号、缺题号或空识别仍会提示不确定，不将缺失当成教师确认空白。

隔离回归：`.venv\Scripts\python.exe -m unittest -q test_answer_card`；先运行 `scripts/single_photo_ui_server.py`，再运行 `node scripts/check_answer_card_ui.cjs` 验证三种上传入口、自动计分、事后改判、打印分页和手机布局。测试不调用真实云端；手写及涂改效果仍需用真实样本验证。

### 答题卡学号栏（2026-11-04）

在班级作业的“上传照片”页顶部打开“答题卡设置（学号栏）”。系统按本次应交名单给出建议（例如六位学号、前缀 `2801`、学生填写后 2 位），老师可修改学号总位数和预印前缀，确认后点“保存本次答题卡格式”，再打印或下载。卡上印出前缀、对应数量的数字方格和模板编号（如 `AC1-TEAFGW`）；学生在方格里每格写一位数字，姓名照写，作为核对依据。

上传时把“照片作答形式”选为“独立答题卡”。识别时系统只从已保存的识别文字中读取学号栏，不额外调用云端。只有读到本次模板编号、学号栏位数完整、全为数字、对应名单唯一，并且照片上没有姓名或完整学号指向另一名学生时，才自动归属，照片卡显示“学号栏匹配 · 268129”。少一位、多一位、非数字、模板编号不符、学号不在名单，或学号与姓名冲突时，都会暂停并写明原因，由老师从名单中选择。系统不会把 O 读成 0，也不会补猜缺位或用剩余名单反推数字。

学号栏仍然是机器读数。学生写错或被误读成另一位学生的学号、且照片上没有其他冲突线索时，系统不一定能发现，请抽查“学号栏匹配”的照片。学号栏匹配的照片可以用“更正机器归属”改选；更正时默认不保存姓名纠错记忆。

格式在本次作业上传第一张照片前可以修改或清除；上传后固定，避免已打印的纸张对不上。格式固定后补充学号不符合格式的学生会被拒绝。未保存格式的作业和任务级答题卡仍打印原有完整学号栏，匹配方式不变。学号含字母、位数不一致的名单暂不适用此功能。

回归：`.venv\Scripts\python.exe -m unittest -q test_student_id_band`（25 项，合成识别文字，不调用云端）。设计与边界见 本机的《统一答题卡与学号识别实施计划》。

## 使用边界

- 支持单词、短语、句子；每题全对才得分，可设置可接受变体。
- 支持打印统一答题纸，也支持上传自由作业本后手动点选或框选题目区域。
- 机器自动计分后教师可对照原图改判；机器未取得作答自动计零分并标记不确定，不视为教师确认空白。
- JPG/JPEG/PNG 单张不超过 10 MB，解码后不超过 2500 万像素。
- 在真实学生样本上测量前，不宣称手写识别准确率。

运行检查：

```powershell
.venv\Scripts\python.exe -m unittest -v test_app test_classes
node --check static/app.js
```

### 横拍及跨段漏行补识别

### 审查修复后的处理方式（2026-10-28）

- 首页分别显示需关注答卷和待确认学生的照片，照片未归属也不会漏报。

- “跳过本题”只切换题目；教师正确／错误／未作答判定和修改仍即时保存。旧建议采纳界面已移除，自动分题和严格评分保留。
- 局部裁切对比报告仍为人工定位实验，不作为正式自动定位能力或识别准确率承诺。

回归：`.venv\Scripts\python.exe -m unittest discover -q`。浏览器：运行 `scripts/audit_fixes_ui_server.py`，再用 Playwright 运行 `scripts/check_audit_fixes_ui.cjs`；仅使用 5035 临时数据，不要改为正式库端口。

处理中照片只在后台进度中显示，不提前要求老师选择学生。此规则只覆盖当前后台批次的照片；统一匹配完成后仍未关联的照片、批次外的异常，以及中断后未解决的照片继续进入人工处理列表。姓名识别失败会保存脱敏后的云端原因（如权限、额度、超时或返回格式），并显示在照片和后台任务记录中；未知错误保留通用提示，不显示原始异常。旧记录中已经丢失的错误细节无法补回，不会因此重新识别。

### AI 自动复核（默认关闭）

本地教师登录后进入“识别设置”，在独立的“AI 自动复核”表单填写 HTTPS 地址、支持图片的模型及 Key，设置每任务题数上限并启用。该配置与主 OCR 分开，按教师隔离；Key 不回显。测试按钮发送系统样例图，可能计费。

后台批改会在完成前复核可可靠定位的不确定短答；已有作业可在异常列表点“AI 复核剩余不确定题”，无需重跑 OCR。只有图片转录与局部 OCR 相互印证才自动解决；空白、冲突、定位不可靠及失败项保留给教师。保留原识别和审计记录，可在本题撤销 AI 判定或由教师改判。每张原图的题目仅自动尝试一次，失败后不会自动重复付费；重启中断的调用按预留额度保守停止，需人工核对。

遇到段落级大框或定位缺失时，复核任务可先用本机缓存的 `PP-OCRv5_mobile_det` 和 `en_PP-OCRv5_mobile_rec` 补精确行坐标。按照片方向转正后识别，再换回原图坐标；用题号和印刷上下文唯一匹配，仍不可靠的区域继续留给教师。补定位不替换原始 OCR，不独立改分，不发起云端 OCR；首次本机加载可能较慢。缺少 Paddle 环境或缓存模型时明确跳过，任务不会自动安装或下载模型。

线上继续使用平台 `VLM_REVIEW_*` 配置，`VLM_REVIEW_AUTO=1` 才启用；教师无权查看或修改平台凭据。当前云端 Docker 运行环境没有本机 Paddle 和模型缓存，部署前需另行准备定位运行环境，不能把本地补定位效果当作线上已具备能力。本地测试不代表真实模型图片支持或手写准确率已经验收。
